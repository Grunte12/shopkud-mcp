# คัดสินค้า Affiliate ด้วย ShopKud

ก่อนใช้ ShopKud ทำงาน Affiliate ครั้งแรก ต้องอ่าน [วิธีทำงานและตัวอย่าง](references/workflow.md) แล้วทำตามคู่มือรุ่นนี้ ใช้หลักฐานและข้อจำกัดจากผลเครื่องมือเป็นหลัก ไม่ต้องอ่านคู่มือเต็มซ้ำต่อสินค้า

- เริ่มจากสินค้าที่เจ้าของกำหนดและประโยชน์ต่อผู้ซื้อ อย่าเปลี่ยนสินค้าหรือกลยุทธ์แบรนด์เอง
- ShopKud รุ่นนี้ specialize เรื่องค้น คัด เปรียบเทียบ และยืนยันสินค้าเท่านั้น งานสร้างวิดีโอ/ภาพ การจัดคิว และการโพสต์เป็น workflow ของ Shopee Affiliate Kit แยกต่างหาก ห้ามอ้างว่า ShopKud ทำสิ่งเหล่านั้น
- ทุกงาน research/selection ต้องใช้ Dashboard template เดิมผ่าน `present_research_report` ห้ามแก้ HTML/JS หรือสร้างหน้าเฉพาะสินค้าเพื่อโชว์ผล กรอก `query`=โจทย์ผู้ใช้, `headline`=ข้อสรุปหนึ่งบรรทัด, `summary`=สรุปการวิจัยและสิ่งที่ยังไม่รู้, `purchase_intent`=เหตุผลซื้อเมื่อเกี่ยวข้อง, `signals`=ปัจจัยตัดสินใจพร้อม rationale/score/source และ `citations`=ลิงก์หลักฐาน ข้อมูล research ภายนอกเป็น Agent-authored research ไม่ใช่สิ่งที่ ShopKud อ่านจาก Shopee ห้ามเปิดเผย private chain-of-thought และห้ามเปลี่ยนความเห็นให้เป็นข้อเท็จจริง
- เริ่ม report แบบ `status="working"` เมื่อมีความคืบหน้าที่มีความหมาย แล้วอัปเดต `report_id` เดิมจน `completed`; รายงานที่เสร็จต้องมีอย่างน้อยหนึ่ง signal พร้อมเหตุผลและหนึ่ง HTTPS citation Human interface หลักคือ Dashboard; แชทใช้สั่งงานและถามต่อ แต่คำแนะนำ ลิงก์ และหลักฐานต้องอ่านตรวจได้บน Dashboard
- งานคัดสินค้าใช้ `rank_affiliate_products` เป็นค่าเริ่มต้น ให้เอเจนต์แปลงเจตนาผู้ใช้เป็น `target_kind`, hard `required_terms`/`excluded_terms`, `ranking_goal`, `freshness` และตัวกรอง แล้วให้โค้ดสแกน กรองความเกี่ยวข้อง ตรวจค่าคอมตามช่องทาง และจัดอันดับในคำสั่งเดียว งานหาสินค้าหลักใช้ `target_kind="product"`; งานหาเคส/ฟิล์ม/อุปกรณ์เสริมใช้ `accessory`; งานยอมรับทั้งคู่ต้องระบุ `any` ห้ามใช้เพื่อแก้ผลว่างโดยพลการ ค่าเริ่มต้นคือ Mall เท่านั้น ยอดขายอย่างน้อย 500 และไม่พรีออเดอร์; งานค้นกว้างต้องส่ง `mall_only=false,min_sold=0,exclude_preorder=false` ชัดเจน และงานไม่เอา Mall ใช้ `exclude_mall=true` ห้ามคลายเงื่อนไขเองเมื่อไม่พบสินค้า
- `winner` จากเครื่องมือเป็นเพียงอันดับหนึ่งตามสูตร ไม่ใช่คำแนะนำที่ Agent ตรวจแล้ว ก่อนแนะนำต้องจำแนก finalist เป็นสินค้าหลัก/อุปกรณ์เสริม/ชุดหรือรุ่นกำกวม/ไม่เกี่ยวข้อง แล้วตรวจประเภทสินค้า แบรนด์ รุ่น ความจุ/กำลัง/ตัวเลือก คุณค่าต่อผู้ซื้อ ร้าน และความพอเพียงของหลักฐานด้วย `get_product_detail(product_url=…,view="brief")` เมื่อเข้าถึงได้ ใส่ `target_model` เฉพาะรหัสรุ่นสั้น เช่น `A1695`; ชื่อรุ่นแบบวลีให้ Agent ตรวจจาก title/description/spec evidence เอง ปฏิเสธ mismatch และ bundle/spec ที่ขัดกัน; ถ้าไม่มีตัวที่ยืนยันได้ให้บอกว่าไม่มี verified target ห้ามยก metric winner มาแทน
- ถ้ามี Product ID หรือ Offer URL อยู่แล้ว ห้ามค้นตลาดซ้ำ ใช้ `get_product_detail(product_id=…,open_if_missing=true,view="brief")` หรือ `offer_url=…` โดยตรง และตอบกลับด้วย `offer_url`/`product_url` ที่คลิกได้ ห้ามส่งเพียงเลข ID หรือขอ short link เพื่อดูสินค้าที่รู้รหัสแล้ว
- ใช้ `scan_products` และ `get_scan_products` เฉพาะงานค้นแบบกำหนดเองที่ playbook ยังครอบคลุม ไม่สแกนซ้ำเพื่ออ่านสินค้าเดิม
- ใช้ `get_product_detail(view="brief")` ตรวจรุ่น/ตัวเลือก ร้าน และค่าคอมเฉพาะช่องทาง เพิ่มข้อมูลเต็มเมื่อจำเป็นต้องตรวจภาพหรือหลักฐานเพิ่มเติม
- ตรวจความน่าเชื่อถือของร้านและข้อมูลการซื้อก่อนจัดอันดับด้วยค่าคอม แยกสิ่งที่เห็นจริง การคำนวณ และข้อมูลที่ยังไม่ทราบ
- ก่อนรับลิงก์ ตรวจ `get_product_history` และประสานงานกับเอเจนต์อื่น ใช้ลิงก์ที่บันทึกไว้แล้วเมื่อยังเหมาะสม การขอรับลิงก์ใหม่ต้องอยู่ในคำสั่งเจ้าของ และไม่ทำซ้ำเมื่อผลไม่แน่นอน
- เก็บตัวเลือกเฉพาะแบรนด์ บุคลิกตัวละคร และรายการที่เจ้าของอนุมัติไว้ในโปรเจกต์ของเจ้าของ ไม่เปลี่ยนให้เป็นกฎทั่วไปของสกิลนี้

ถ้าอ่านผ่าน MCP แทนไฟล์ ใช้ `get_workflow_guide(view="full")`; `view="brief"` คืนรุ่นและแผนที่เครื่องมือโดยไม่ส่งคู่มือเต็ม ไม่แก้การตั้งค่าเอเจนต์หรือติดตั้งสกิลให้อัตโนมัติ
